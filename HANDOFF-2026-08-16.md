## Traps worth remembering

1. **Flex reads `installed.json`, not the `mono/link` symlink.** Adding the `symfony-ux`
   keyword to a mono bundle does nothing in any app until a release reaches Packagist. Until
   then Flex *deletes* the controllers.json block on every composer operation, and a
   hand-restored block is wiped again on the next run.
2. **Flex recipes edit `scripts`.** `composer require otezvikentiy/json-rpc-api` re-added a
   plain `"cache:clear": "symfony-cmd"` to auto-scripts, reverting `c5ca241` and breaking the
   deploy with a 128M OOM in Twig warmup. **Diff `scripts` in composer.json after every
   `composer require` in a deployed app.** `php.ini` is not the lever — it applies to FPM at
   runtime, not to the build, which is why the error says 128M while the file says 512M.
   Never put comment keys in `auto-scripts`; every key there is executed.
3. **`:prevent` is a Stimulus action option and belongs after the METHOD.**
   `stimulus_action(_sc, 'x', 'submit:prevent')` renders `submit:prevent->…#x`, which Stimulus
   silently ignores. Put it on the action: `stimulus_action(_sc, 'x:prevent', 'submit')`.
4. **Verify Stimulus wiring against the generated controllers map**, not by reasoning about
   naming rules: pull `/assets/@symfony/stimulus-bundle/controllers-*.js` out of a rendered
   page's importmap and read `eagerControllers`/`lazyControllers`.

## Open — not done, deliberately

- **`AiPipelineBundle` stale imports.** `src/Workflow/AssetWorkflow.php:30` and
  `src/Command/MediaFixtureCommand.php:12` import
  `Survos\AiPipelineBundle\Task\{AiTaskInterface,AiTaskRegistry}` — a bundle renamed to
  ai-workflow, and those class names no longer exist under either namespace (now
  `TaskInterface` / `TaskRegistry`). PHP returns **false** for `instanceof` against a missing
  class *silently*, so `AssetWorkflow:120`'s `$task instanceof AiTaskInterface` never matches
  and `$aiTaskHandlers` is always empty. AI tasks work because `AssetController` uses a
  different registry/executor path. Repointing them would *activate* a long-dead code path —
  a deliberate behaviour change, not a rename.
- **Test DB drift.** Tests run against `mediary` (from `.env`; Symfony skips `.env.local` in
  the test env) while dev uses `mediary-temp`. That DB is behind 2 migrations plus five
  bundle-added columns (`media.dataset`, `media.ai_*`, `asset.face_count`), which is the one
  failing test (`/api/media` 500).
- **`/info` backfill.** Only 19 of 3492 assets have a `faceCount`, so the new facet is sparse.
- **API Platform MCP cannot serve a read tool for Asset.** `McpTool extends HttpOperation` but
  does not implement `CollectionOperationInterface`, so a collection tool cannot be expressed;
  an item tool never runs a state provider and just echoes the arguments back. Details in
  `doc/JSONRPC.md`. **ssai's `Acc` uses the identical pattern and is very likely returning
  empty objects too — worth checking.**
- **Duplicate-facet guard.** A fix that never crossed the ux-search absorption is preserved as
  follow-up 4 in `mono/bu/search-bundle/docs/consumer-migration.md`. `addFacet()` still just
  appends, so the bug is live. Applying it turns a silent no-op into a `LogicException` —
  check all four apps first.
- **`live#action` literals.** Seven sites in search-bundle templates hard-code `live#action`.
  Correct today (LiveComponent pins the bare `live` identifier via a `name` override in its
  package.json), but they also hand-roll `data-live-*-param` attributes — same trap one layer
  down.
- **zenstruck/messenger-monitor.** The `$aliasMap` deprecation is already fixed upstream
  (PR #175, merged 2026-08-09) but unreleased; v0.6.0 predates it. Nothing to file.

sha256 → S3 archive → imgproxy `/info` → exif (46 keys) + dimensions + 1 face each at 0.84/0.87

is not required for it — but archiving is currently **active**, not disabled.
